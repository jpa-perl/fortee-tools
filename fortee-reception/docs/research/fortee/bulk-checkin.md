# 一括チェックイン

管理画面「参加者 → 一括チェックイン」（`/{conf}/organizer/attendees/bulk-checkin`）は、CSV ファイルをアップロードしてチェックイン状態を反映する。

## CSV の形式

```csv
profile_url_token,checkined_at
XXXYYYZZZ,2025-01-23T04:56:00+09:00
```

- ヘッダの綴り（`checkined_at`）は画面表記のままにする
- キーは profile_url_token であり、QR に入っているチケットトークンではない（[data-model.md](data-model.md) の「2 種類のトークン」）
- イベントの指定はない。profile_url_token だけで参加者が特定され、複数イベントの参加者を 1 ファイルに混在させてよい

## 挙動

いずれも Sandbox で確認した。

| 入力 | 結果 |
| --- | --- |
| 正しい profile_url_token と ISO 8601 の日時 | 成功。チェックイン日時は CSV の値（17:30 を指定すると 17:30）になる |
| 既にチェックイン済みの参加者を再度含める | 成功。日時は CSV の値で上書きされる |
| `checkined_at` が空 | 成功。日時はアップロード時刻になる |
| `2026-11-07 20:00:00`（タイムゾーンなし） | 成功。20:00 として記録された（JST 扱いと推定） |
| 存在しないトークン | 失敗: Attendee not found。他の行は処理される |
| チケットトークン（`fortee:` の有無を問わず） | 失敗: Attendee not found |
| 複数イベントの参加者を 1 ファイルに混在 | 行ごとに処理され、どちらも成功 |

CSV に含まれない参加者の状態は変わらない。一括チェックインは「チェックイン済みにする差分の適用」であり、未チェックインに戻す手段はこの機能にはない。戻すにはチェックイン API で `unused` を送るか（[checkin-api.md](checkin-api.md)）、参加者詳細画面で手動解除する。

処理結果は同じ画面に「成功: n件 / 失敗: m件」と、行ごとの「プロフィールURLトークン / チケット番号 / 取り込み結果」の表で表示される。行数の上限は未確認である。
